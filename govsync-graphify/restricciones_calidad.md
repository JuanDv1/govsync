# Restricciones Técnicas y Atributos de Calidad

Los atributos de calidad y restricciones técnicas del sistema se han extraído directamente de las especificaciones y necesidades operativas de los municipios de categoría 6 [93]:

| Tipo de Atributo | Atributo Específico             | Especificación Técnica                                                                                                                                                                                  |
| :--------------- | :------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Integridad**   | Protección de datos financieros | Los datos financieros provenientes de los archivos cargados en el corte no podrán ser modificados mediante ninguna funcionalidad del sistema [93].                                                      |
| **Integridad**   | Versionamiento de cortes        | Una nueva carga de información en una misma vigencia deberá generar una nueva versión del corte, conservando las versiones anteriores de forma histórica sin sobrescribirlas [94].                      |
| **Fiabilidad**   | Validación de archivos          | El sistema deberá validar de forma estricta la estructura de los archivos cargados (ingesta) y rechazar aquellos que no contengan las columnas obligatorias definidas para cada fuente [94].            |
| **Fiabilidad**   | Detección de inconsistencias    | El sistema deberá identificar y reportar las inconsistencias parametrizadas en las reglas de negocio entre las fuentes cargadas (ej. descuadres de compromisos vs. contratos) [94].                     |
| **Trazabilidad** | Origen de los datos             | Los resultados consolidados en la matriz de relación deberán permitir identificar claramente el corte y las fuentes de información utilizadas para su generación [95].                                  |
| **Seguridad**    | Autenticación y autorización    | El acceso a todas las funcionalidades del sistema deberá requerir autenticación obligatoria y estar restringido según el rol. La autorización deberá validarse de forma obligatoria en el backend [95]. |
| **Seguridad**    | Cifrado en tránsito             | Toda la comunicación entre el navegador de usuario y el servidor de aplicación deberá realizarse mediante el protocolo HTTPS de forma obligatoria [95].                                                 |
| **Rendimiento**  | Tiempo de procesamiento         | El procesamiento, validación, transformación y cruce de datos de un corte de referencia del municipio piloto (Santa Rosa) deberá completarse en un tiempo máximo de **60 segundos** [96].               |
| **Rendimiento**  | Tiempo de respuesta             | Las vistas principales del sistema (dashboard, plan de acción consolidado) deberán cargarse en un tiempo máximo de **4 segundos** utilizando el conjunto de datos de referencia de Santa Rosa [96].     |
| **Usabilidad**   | Registro de avance físico       | Un supervisor sectorial deberá poder registrar el avance físico de una meta desde una única vista unificada, sin necesidad de navegación intermedia entre múltiples módulos [96].                       |
